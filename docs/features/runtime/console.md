# 运行控制台与日志采集

[功能索引](../README.md) · [运行时模块](README.md)

当前状态为新增代码与模拟界面验证，真实服务验收待完成。

## 使用入口

侧栏「运行控制台」打开 `/logs`。页面采用现有浅色工作台和深色日志阅读区，支持深色主题和手机布局。日志视图提供级别、模块、关键词与本地日期筛选，展示来源、行号、异常字段和关联编号，支持复制记录、暂停更新及加载更早记录。错误信息按纯文本显示。

实时更新每 2 秒查询一次增量，按游标读取最早未读前缀。筛选变更取消旧请求并清空原筛选结果，历史日期暂停自动追加。页面缓存最多 2000 条。

「进程与组件」显示本进程 PID、CPU、内存与运行时长，受监督组件的运行、停止、退避和失败状态、重启次数及最后状态时间。平台连接和 Bash 注册状态来自当前装配实例。子进程列表最多 64 项，最多遍历四层父子关系，展示进程名、PID、内存和存活时长。CPU 首次采样缺少历史差值时可能为零。WebUI 无法访问时需要使用服务管理或容器日志排查。

## 日志来源与存储

启动装配通过 `tracing-subscriber` Layer 捕获 Rust 日志及 span 字段，沿用终端输出。ERROR 可保留原始异常链、模块、文件和行号。panic 钩子额外保存有界 Rust backtrace，其他错误的堆栈取决于原调用点提供的信息。

进程内保留最近 2000 条，启动时从现有 `data/logs/runtime.jsonl` 及轮转文件恢复末尾记录。后台写盘使用有界队列，队列满时计数并保留内存记录。当前文件约 2 MiB 后轮转，保留三份备份。每条消息最多保留 8192 个字符，字段最多 24 项且合计限 12288 个字符。

页面显示采集级别、写盘状态、丢弃写入数、磁盘错误数和增量缓存缺口。Unix 日志文件权限为 `0600`。关闭时尝试等待写盘队列完成，最长两秒；进程被强制结束时末尾记录可能丢失。

采集级别从启动时的 `log.level` 加载，默认 INFO，配置变更需重启生效。历史错误的当前影响需要结合组件状态和实际请求核实。

## 访问与脱敏

`GET /api/logs` 和 `GET /api/runtime/status` 沿用管理员 Bearer 会话鉴权。日志接口支持 `level`、`target`、`search`、毫秒范围 `from_ts` / `until_ts`、排他游标 `before_id` / `after_id` 和 1–200 条分页，同时返回缓存边界及增量缺口。

启动前注册主配置与 Provider 凭据，插件加载前注册已有配置的敏感字段；面板提交新配置时同步注册新值。写入前替换已知凭据、敏感字段、常见认证值和远端 URL，读取缓存时再次脱敏。管理员仍应核对导出的错误内容，避免在命令或日志中主动输出私密材料。

云团的[自检](../core/diagnostics.md)可查询有消息编号和会话归属的 WARN / ERROR。宿主核对当前提问者在当前会话的原消息归属后才投影记录。全局日志和进程界面提供管理员诊断入口。
