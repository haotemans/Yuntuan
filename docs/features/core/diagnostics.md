## 使用与记录来源

在聊天中发送 `/自检` 或 `/diagnose`，查询最近 60 分钟的运行记录。可在命令后填写本地消息编号以聚焦一次请求。命令通过宿主 Skill 直派，即使模型角色暂不可用也可读取数据库并生成固定格式结果。

自然语言询问云团自己的报错时，Decision 可选择 `diagnostics.recent`。同名 Tool 提供 `minutes`、`limit`、`message_id` 参数，分别限于 1–1440 分钟、1–20 条和正数本地消息编号。默认最多返回 10 条，并提供是否存在更早记录的标记。

查询复用消息判断状态、图片状态、技能调用、任务工具回执和 `RuntimeFailure` 事件。每条返回阶段、记录来源、来源编号、消息编号、时间、状态、固定错误码与中文说明。

图片 `pending` 表示图片已收到但尚未触发识图，`processing` 表示已经开始等待结果，`failed` 表示识图已失败。现有 `image_or_provider` 原因粒度覆盖图片与服务两端，输出明确保留该不确定性。

## 查询与执行边界

所有来源按宿主注入的会话类型、会话 ID 和提问者身份过滤。参数中可指定本人的消息编号，跨人或跨会话编号返回空记录。命令调用检查 Skill 开关，Skill 委托 Tool 时再检查 Tool 开关、会话范围和参数。工具按只读契约运行。

原始异常、服务响应正文、图片地址、凭据、工具参数、任务目标和其他用户消息保留在各自原记录中。对话诊断使用固定错误码投影。错误码可指出超时、认证拒绝、权限、限流、格式或结果待核实，记录不足时明确提示需要进一步核实。

回复生成与实际发送失败新增带会话类型、原消息编号、阶段和固定错误码的 `RuntimeFailure` 观测事件。Tracer 沿用现有保存与轮转策略。旧版运行期间未保存的这类记录，以及事件消费滞后造成的缺失，都会限制诊断覆盖范围。查询无记录时只说明当前范围未查到记录。修复配置、重启和重新执行需对应操作授权。
